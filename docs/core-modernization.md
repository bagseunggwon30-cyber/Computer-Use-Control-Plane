# CUCP 범용 실행 코어 개발 방향

## 목표와 범위

CUCP를 **Computer Use 기능이 없는 에이전트 호스트에 넣는 Windows 관찰·실행 계층**으로 개발한다. 첫 연결 대상은 Pi이며, 같은 코어를 다른 호스트에서도 호출할 수 있도록 모델 제공자와 실행 계약을 분리한다.

특정 PLC·CAD 프로그램 프로필을 추가하는 확장은 개발 범위에서 제외한다. 우선 대상은 창, 포커스, 이미지 좌표, 텍스트 입력, 키, 스크롤, 공통 오류와 복구 판단에 필요한 관찰이다. 기존 앱 관련 레거시 명령은 별도 호환 경로에 남으며 새 코어의 완성도를 평가하는 기준으로 사용하지 않는다.

모델 선택·API 키·대화·추론은 Pi 같은 호스트가 맡는다. CUCP 안에 또 다른 LLM이나 자율 계획 에이전트를 넣지 않는다. 언어별 코드 비율도 목표로 삼지 않는다. Python은 세션과 계약을, C#은 Windows 기능을, PowerShell은 준비와 시작을 맡는 역할 경계를 우선한다.

## 이번 구현과 후속 기능의 구분

| 영역 | 이번 구현 | 후속 단계 |
| --- | --- | --- |
| 연결 | Pi TypeScript 확장, 상주 Python JSONL 세션 | 다른 호스트 어댑터·MCP 필요성 검토 |
| Windows 실행 | Python 세션당 지연 시작하는 상주 C# 프로세스 | 제한된 인터페이스의 별도 관리자 브로커 |
| 관찰 | 지정 창 화면, UIA 트리, HWND/PID, 좌표 변환 정보 | 유효기간 있는 UIA 요소 참조, 이벤트 관찰, 영역 확대 |
| 입력 | 단일 클릭, Unicode 입력, 제한된 키/조합키, 스크롤, 명시적 포커스 | 드래그·추가 조작을 공통 시험으로 검증 후 추가 |
| 배치 | 최대 12단계, 순서대로 실행, 실패 시 나머지 중단 | 관찰 조건이 명확한 대기·사후 조건 계약 |
| 권한 | 기본 조작 꺼짐, 호스트가 켬, 권한·보안 데스크톱 진단 | 제한된 인터페이스의 선택적 관리자 브로커 |
| 완료 판단 | 입력 전달 결과와 다음 화면을 분리해 반환 | 호스트가 명시한 검증 조건의 평가 |
| 기록 | 세션 내 제한된 요청 결과 메타데이터 | 명시적인 저장 정책과 재현 가능한 평가 기록 |

상주 네이티브 단계에서는 Python `serve`가 같은 C# 프로세스를 재사용한다. 프로세스 시작 비용을 반복하지 않지만 실제 지연 개선은 측정 전이다. UIA 구독·요소 참조 캐시와 별도 관리자 브로커는 아직 구현하지 않았다. [상주 세션 계약](resident-native-session.md)을 참고한다.

## 현재 연결 계약

실제 스키마와 허용 필드는 `pcucp-next/python/pcucp_cli/engine.py`, `registry.py`와 Pi 확장에서 관리한다. `serve` 프로세스 하나가 세션 하나를 소유한다. 요청은 UTF-8 JSONL이며 한 줄당 JSON 객체 하나이다.

요청 예시:

```json
{"schema":"cucp.request/v1","id":"windows-1","command":"windows","args":{}}
{"schema":"cucp.request/v1","id":"observe-1","command":"observe","args":{"hwnd":"0x1234","pid":5678,"include_ui":true}}
```

`hwnd`와 `pid`는 실행 시점에 `windows`가 반환한 실제 값으로 바꾼다. 요청 ID는 호스트가 생성한다. 세션의 최근 1,024개 ID 중 중복 ID는 거부하며, 재시작을 넘는 영구 중복 방지나 exactly-once 실행을 약속하지 않는다.

응답 형태:

```json
{
  "schema": "cucp.response/v1",
  "id": "request-id",
  "command": "observe",
  "status": "ok",
  "data": {},
  "errors": [],
  "duration_ms": 12.3
}
```

위 응답은 외형 예시다. 실제 `data`에는 명령별 결과가 들어간다. 최상위 `status`는 `ok`, `partial`, `error`, `blocked`를 사용한다. 배치의 미실행 단계는 별도로 `skipped`이다. 오류는 코드와 설명을 보존하며, 빈 검색 결과와 관찰 제공자 실패를 같은 의미로 취급하지 않는다.

| 명령 | 주요 인자 | 의미 |
| --- | --- | --- |
| `capabilities` | 없음 | 지원 명령, 키, 조작 모드, 제한 확인 |
| `windows` | 없음 | 창 목록, 핸들과 소유 PID |
| `observe` / `screenshot` | `hwnd`, 선택 `pid`, `include_ui`, `max_width`, `max_height` | 명시적 창 관찰 및 새 관찰 ID |
| `uia-tree` | `hwnd`, 선택 `max_depth`, `max_nodes` | 제한된 구조 관찰; 실행할 수 있는 영구 참조가 아님 |
| `privileges` | 선택 `pid` | 현재 프로세스와 대상의 권한 진단 |
| `focus` | `hwnd`, `pid` | 대상 활성화 후 화면 수집 |
| `click` | `observation_id`, `x`, `y`, 선택 `button` | 반환 이미지 좌표의 단일 클릭 |
| `type` | `observation_id`, `text` | 현재 입력 위치에 Unicode 텍스트 전달; 길이 1~4,096자 |
| `key` | `observation_id`, `keys` | `capabilities.keys`에 있는 키/조합키 |
| `scroll` | `observation_id`, `direction`, `amount` | 현재 포인터 아래 대상에 휠 입력; 양 1~20 |
| `batch` | `actions`, 선택 `observe_after: true` | 최대 12단계 실행, 첫 실패에서 중단 |
| `history` | 없음 | 현재 세션의 최근 결과 메타데이터; 입력 내용·이미지 영구 저장 없음 |

Pi는 이 계약 중 여섯 도구를 노출한다: `cucp_windows`, `cucp_observe`, `cucp_action`, `cucp_batch`, `cucp_capabilities`, `cucp_privileges`. 관찰 명령 전체를 별도 도구로 늘리지 않는다.

## 관찰 ID와 좌표

기본 관찰 유효시간은 60초이며, 새 관찰은 이전 ID를 대체한다. 입력을 시작할 때 이전 ID를 무효화하고 성공한 입력 뒤 새 화면과 새 ID를 수집한다. 취소·재시작·실패 뒤에는 이전 ID를 재사용하지 말고 다시 관찰한다.

```json
{
  "schema": "cucp.request/v1",
  "id": "click-1",
  "command": "click",
  "args": {"observation_id": "관찰에서 받은 ID", "x": 120, "y": 80, "button": "left"}
}
```

클릭 `x`, `y`는 **CUCP가 반환한 PNG의 `image.width`, `image.height` 기준**이다. Python이 이미지 좌표를 물리 화면 좌표로 변환한다. 가상 데스크톱의 음수 원점과 창 일부만 화면에 들어오는 경우를 표현할 수 있다. Pi가 모델에 전달하며 이미지를 다시 줄인 경우에는 Pi의 치수 안내를 적용해 CUCP 원본 이미지 좌표로 환산해야 한다.

현재 캡처는 **화면에 보이는 데스크톱의 창 영역을 잘라낸 이미지**다. 다른 창에 가려진 부분에는 그 다른 창이 포함될 수 있다. 최소화·화면 밖 창의 내부 내용을 렌더링하는 기능이 아니다. UIA 트리도 이미지와 원자적으로 같은 순간에 캡처되지 않는다.

C# 입력 직전에는 창 존재·PID·예상 창 위치와 크기·전경 상태를 확인한다. 클릭은 그 지점의 실제 창도 확인한다. 스크롤은 포인터가 대상 밖에 있으면 멈춘다. 글자 입력은 포커스된 편집 요소의 의미까지 보장하지 않으므로 호스트가 화면/UIA를 보고 먼저 입력 위치를 선택해야 한다. 같은 창 내부 UI만 바뀌면 창 크기 검사가 이를 탐지하지 못할 수 있다.

## 실행과 검증 의미

`SendInput`이 요청한 이벤트 수를 받아들였는지 검사한다. 이 결과는 OS 입력 전달 결과이며, 앱이 의도한 값을 받아 저장했다는 증거는 아니다. 조작 뒤 화면을 다시 얻었을 때도 `verification: observed_not_asserted`를 유지한다.

호스트는 다음 화면이나 읽을 수 있는 상태를 보고 작업 목표를 확인해야 한다. 예를 들어 “저장 단축키 전달”, “저장 대화상자 닫힘”, “파일 존재 및 내용 확인”은 서로 다른 근거다. 화면을 얻지 못했다면 조작이 이미 일어났을 수 있으므로 실패를 보고하고 재관찰한다. 자동 반복 입력이나 임의 Ctrl+Z 복구를 수행하지 않는다.

배치 예시:

```json
{
  "schema": "cucp.request/v1",
  "id": "batch-1",
  "command": "batch",
  "args": {
    "actions": [
      {"command":"click","args":{"observation_id":"관찰에서 받은 ID","x":120,"y":80}},
      {"command":"type","args":{"observation_id":"latest","text":"테스트 입력"}}
    ],
    "observe_after": true
  }
}
```

`latest`는 배치 두 번째 이후 단계에서만 허용한다. 현재 구현은 단계마다 후속 화면을 얻는다. 배치 결과에는 단계별 성공·실패·미실행과 마지막으로 얻은 이미지가 들어간다. 실패 뒤 이미지가 실패 이전 상태일 수 있으므로 다시 관찰해야 한다. 분기·반복 코드를 실행하는 배치가 아니며, 다음 화면을 봐야 좌표를 결정할 수 있는 작업은 단일 호출로 나눈다.

## 권한 설계

목표는 일반 사용자 앱과 허용된 관리자 앱의 조작 가능성을 명확히 진단하는 것이다. 모든 프로세스보다 위에서 실행해 보안 경계를 없애는 구조는 채택하지 않는다.

현재는 사람이 `start-pi.ps1 -Elevated`를 선택하면 Windows의 정상 UAC 승인을 거쳐 **Pi 전체**를 관리자 권한으로 시작한다. Python과 네이티브 자식도 이 실행 권한을 이어받는다. CUCP의 조작 모드는 여전히 기본 꺼짐이며, 별도로 `/computer on`이 필요하다.

- 일반 실행에서 더 높은 무결성의 대상에 접근하면 `elevation_required`를 반환한다.
- 권한 조회에 실패하면 가능하다고 추정하지 않고 오류를 반환한다.
- UAC 보안 데스크톱·로그인 화면·SYSTEM/PPL 우회는 지원하지 않는다.
- 권한 비교 통과도 앱별 입력 수용을 보장하지 않는다.
- Pi의 bash나 다른 확장까지 CUCP가 제한하지 않는다. 관리자 실행은 이들 도구의 권한도 높인다.

후속 네이티브 브로커는 사용자 세션 소유권, 제한된 명령, 인증된 로컬 통신, 취소와 수명 관리부터 설계한다. `UIAccess`는 코드 서명·설치 조건과 배포 목적을 검토할 별도 옵션이며 현재 앱 manifest로 보안 경계를 우회하는 기능이 아니다.

## 단계별 개발 순서와 완료 기준

### 1. 연결 가능한 최소 실행 코어 — 이번 구현

공통 레지스트리, JSONL 응답, 대상이 명시된 관찰·입력, Pi 이미지 결과, 실패 전파, 시간 제한·취소, 짧은 배치를 제공한다. 게시된 C# 실행 파일을 사용하고 입력 경로에서 `dotnet run`과 구 PowerShell 자동 폴백을 제거한다.

완료 판단은 코드 작성 여부와 실행 증거를 나눈다. 모의 Windows 결과로 계약·취소·오류를 검증할 수 있지만 실제 Windows 입력 검증은 별도다. 이번 개발 환경에서는 **실제 Windows GUI·IME·UAC·다중 모니터 검증을 수행하지 못했다.**

### 2. 일반 UI 시험장과 Windows 실행 검증

새 앱 프로필 대신 다음 조건을 포함한 공통 시험을 만든다. 사람의 작업 환경을 바꾸지 않는 전용 테스트 창과 임시 데이터로 실행한다.

| 시험 | 판정 근거 |
| --- | --- |
| 텍스트·한글·기호 입력 | 편집 컨트롤의 실제 최종 값 비교 |
| 클릭·선택·스크롤 | 목표 컨트롤 상태, 잘못된 대상 조작 유무 |
| 포커스 전환·가림·창 종료 | 다른 창으로 입력하지 않고 명시적 실패 반환 |
| 창 이동·크기 변경·DPI 125/150% | 이전 관찰 거부 또는 올바른 좌표 매핑 |
| 왼쪽·위쪽 보조 모니터 | 음수 물리 좌표와 화면 가장자리 처리 |
| 시간 초과·취소·엔진 종료 | 자동 재전송 없음, 부분 실행 가능성 보존 |
| 일반/관리자 대상 | 권한 부족 진단, 사람의 승격 후 재관찰 |
| 배치 도중 실패 | 이후 단계 실행 수 0, 성공/실패/미실행 구분 |

작업 성공률, 잘못된 대상 입력 수, 복구 성공률, 지연 p50/p95, 이미지 바이트와 호스트 모델 사용량을 따로 기록한다. 명령 수와 실패 표본을 버린 평균으로 품질을 판단하지 않는다. 모델별 비교는 같은 작업·초기 상태·예산에서 수행한다.

### 3. 상주 네이티브 브로커와 구조 기반 실행

C# 프로세스 재사용은 구현했다. 2단계에서 확인한 호출 비용과 실패 유형을 근거로 수명 관리와 관찰 기능을 확장한다. UIA 요소 참조에 소유 프로세스·관찰 세대·유효기간을 연결하고, 오래된 참조는 재탐색하게 한다. 의미가 맞는 UIA Pattern을 실행한 뒤 상태를 읽는 경로를 추가한다. 프로세스 상주만으로 UIA 정체성이나 안정성이 자동으로 해결되지는 않는다.

### 4. 필요한 관찰만 전달

창·포커스·UIA 변화 이벤트, 화면 변화 요약, 안정화 대기, 작은 영역 확대를 추가한다. 이미지와 구조 정보의 예산은 호스트가 선택할 수 있게 하며, 모델별로 같은 시험에서 비용·정확도를 비교한다. 더 많은 이미지가 항상 더 좋은 결과를 만든다고 가정하지 않는다.

### 5. 다른 호스트로 확장

새 호스트에는 도구 설명, 이미지 콘텐츠 변환, 수명/취소 연결만 얇게 추가한다. 모델별 computer-use toolset이나 MCP를 붙일 때도 기존 실행 계약과 검증을 재사용한다. 독립 LLM 호출, 임의 코드 실행 샌드박스, 절차 학습은 현재 기능으로 포함하지 않으며 필요성과 별도 검증이 확인된 뒤 판단한다.

## 레거시와의 관계

기존 PowerShell에는 CDP 임의 실행 분류, probe 입력·undo, 입력 전달 실패, 좌표 0/음수, 근거 없는 측정 통과와 같은 직접적인 문제를 제한적으로 수정했다. 이는 전체 레거시 런타임을 새 계약으로 통합했다는 뜻이 아니다. 새 Pi 도구는 레거시 매크로를 자동 실행하지 않는다.

레거시 네이티브 helper는 신뢰하는 로컬 내부 인터페이스이며, wrapper의 live gate는 OS 전체 보안 경계가 아니다. 일부 다른 레거시 좌표 매크로와 상주 PowerShell helper의 동작 차이도 남아 있다. 신규 기능과 개선 검증은 새 코어에 집중한다.
