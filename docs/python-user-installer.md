# User-scope Python installer migration

The original installer logic and source entrypoint are implemented in Python.
`python install.py` preserves `-BinDir`, `-NoPathShim`, `-Quiet`, `-Backend`,
`-PortableRoot` and `-PythonExe`, and applies installation as the old entrypoint did.
Use `python install.py --plan` to inspect without writes. `install.ps1` has been deleted.
Nothing here installs software, requests elevation, starts a model or modifies a
user's real launcher directory during tests.

## Backend selection and dependencies

`python pcucp-next/packaging/install_runtime.py` plans a **legacy** installation by
default, matching the original installer. `--apply` explicitly performs the selected
file changes and bounded health check. It does not silently redirect legacy macros
to the new core's different interface.

- `--backend legacy`: retained `scripts/cucp.ps1`; Windows PowerShell 5.1+ remains a
  runtime prerequisite. Generated ASCII `cucp.cmd` invokes a sibling UTF-8-BOM
  `cucp-launch.ps1` containing the safely quoted source path. Build the matching
  native host and compatibility assemblies before using migrated legacy routes:
  `publish_native.py`, `publish_legacy_interop.py` and `publish_legacy_images.py`
  under `pcucp-next/packaging`. The last supplies the file-image and shared OCR
  helpers; it uses .NET Framework 4.8 on Windows. The installer does not build or
  download missing dependencies, and its health warning is not a parity check
- `--backend core`: source Python 3.10+ and the matching published native worker.
  Generated UTF-8 `cucp.cmd` invokes Python and `pcucp-next/python/run_source.py`
  directly, with the correct process-local `CUCP_ROOT`. PowerShell is not required
- `--backend portable --portable-root ...`: explicitly selected folder containing
  `CUCP.exe`. Generated UTF-8 `cucp.cmd` invokes that executable directly. Runtime
  Python and PowerShell are not required; the bundle supplies its runtime

Running this source installer itself requires Python 3.10+, including when selecting
the portable backend. Portable users can instead unzip/run their bundle without
using an installer. No dependency or native worker is downloaded or rebuilt.

Direct cmd launchers save/restore the console codepage, switch to UTF-8 before
non-ASCII path lines, disable delayed expansion, escape literal percent signs in
paths, and preserve the child exit code. Arguments are forwarded as supplied to
cmd.exe; this is not an escaping layer for arbitrary command strings generated by
other tools. Callers must quote shell metacharacters normally. Runtime flags are
not added: human-selected live authority remains a startup decision.

## Exact writes, replacement and deletion

The default destination remains `%LOCALAPPDATA%\Microsoft\WindowsApps`; `--bin-dir`
selects a different directory. `--no-path-shim --apply` runs only the selected health
check and does not create launcher files. `--quiet` suppresses normal output.

The installer writes only `cucp.cmd`, the legacy-only `cucp-launch.ps1`, and an
ownership manifest `.cucp-install.json`. Temporary files stage atomic replacements.
Ordinary write errors trigger best-effort restoration of the prior known contents;
this is not a transactional guarantee against power loss or unrelated concurrent
writers. PATH, registry, startup tasks, persistent environment variables, security
settings and backend source files are unchanged.

Existing unowned files or edited owned files are refused rather than overwritten.
This deliberately repairs the previous silent-overwrite behavior. A launcher created
by the old installer has no ownership manifest: preserve or move it manually before
adopting the new installer. Changing backend requires explicit removal first.

`--uninstall --apply` checks every generated file's recorded hash before deleting
only those files and the manifest. It does not remove the directory or unrelated
files. Edited/missing/symlinked files cause refusal. Uninstall does not need the source
checkout or backend executable to remain available.

Legacy health uses the same `-Brief macro health-quick` purpose; core/portable use
`doctor --json`. Health failures are reported as warnings and remain nonfatal as in
the original installer, with a new 30-second bound. No live-control flag is added.

## Parity evidence and remaining Windows checks

Pure filesystem fixtures cover backend selection, Unicode templates, no-write plans,
ownership, refusal of edited files, explicit backend transitions, rollback, bounded
health argv and unchanged unrelated files. Windows-only tests execute disposable
fixture scripts through cmd and PowerShell to verify Unicode paths, argument forwarding
and exit codes; they do not call a real CUCP action or install to WindowsApps.

`python pcucp-next/packaging/start_pi.py` replaces `start-pi.ps1`; `--elevated`
uses ShellExecuteExW with the normal UAC consent and waits for the selected Python
session's exit code. It does not construct or execute a PowerShell command.
The entire Pi session is elevated, as before; live control still starts off.
`--python-exe`/`-PythonExe` and `--pi-executable`/`-PiExecutable` select executables.
The ordinary Windows npm batch-shim route has been tested with owned recorders
under Korean, space, percent, exclamation and ampersand paths, preserving the
extension argument, environment and exit code. Actual UAC approval and Pi startup
have not been exercised by these tests.

`cucp-next.ps1` and `publish-native.ps1` have also been deleted. Their replacements
are `python pcucp-next/python/run_source.py` and
`python pcucp-next/packaging/publish_native.py`. Publishing accepts the original
`-Runtime` and `-OutputDirectory` spellings as well as the Python options.
The native runtime is built explicitly, never during an action.

The legacy/core Unicode launcher and argv fixtures passed on a real Windows runner
for commit `fc05aa01a0632b36af930a522efe8c623037300b`, Actions run `36886830685`,
job `110452169750`, installer qualification step. That qualified replacing the
original installer body. A separate Windows test now copies the compatibility shim
into a disposable fixture with an argument-recording Python installer to check all
preserved switches, explicit backends and exit-code propagation.

The Python entrypoint requires Python 3.10+ for source installation; the default
backend remains legacy, with its PowerShell root wrapper still present.

The four retired PowerShell launcher/build files are no longer tracked source.
This is partial migration: the legacy wrapper and other PowerShell source/tests
still prevent a 0% repository result. No Linguist exclusions are used.
